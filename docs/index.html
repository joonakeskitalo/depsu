Dependency updates made easier

depsu is a terminal UI for updating npm, yarn, pnpm and bun projects. It works like npm-check-updates, but the list stays open after an install. It also shows how your overrides affect each package and checks for vulnerabilities.

Features

Everything in one list

Browse outdated packages, install them one after another, and handle overrides, vulnerabilities, peers and commits without leaving the terminal.

▤

Uses your package manager

npm, yarn, pnpm or bun, detected from the project. Monorepos work because lockfiles are searched in parent directories.

⌁

Uses your registry

Reads .npmrc, .yarnrc.yml and bunfig.toml, including private registries, scopes and auth tokens.

^~

Version range at a glance

The prefix is colored: ^ yellow, ~ cyan, >= red. No prefix means pinned exactly.

☰

Select, group, filter

Group by release type, name prefix or dependency type. Filter by name. Select one package, a whole group, or all.

⚑

Override aware

Shows overridden packages, checks that an update fits the override, finds unneeded overrides, and updates or removes them.

✱

Vulnerabilities

Findings from Snyk, npm audit or bun audit, shown under the dependency that brings them in. Install the suggested fix with one key.

?

Details panel

Deprecation, install scripts, size, engines, platform, integrity checksum, dependents, peers and dependency changes.

⚠

Peer dependency checks

An update that needs other packages to change lists them and asks. Unmet peers can be fixed from a dialog.

⛔

Blocked version handling

For registries with a security policy, depsu checks downloads first and offers the newest version that can be installed.

±

Edit, add, pin, delete

Set any version, add packages, choose the pin type, delete packages and overrides, all from dialogs.

⎇

Conventional commits

Press c to commit package.json and the lockfile with a generated, editable message.

Installing

Install, then keep going

Select packages with space, or highlight one, and press i. The install runs in the background while you keep browsing.

  • Peer dependencies. If an update needs other installed packages to change, depsu lists them. y updates them too, n installs only what you picked, any other key cancels.
  • One install for mixed flags. Packages that need different flags (dependency or dev dependency, exact or range) are written to package.json together and installed at once. If that fails, package.json is restored.
  • Your range prefix is kept. ^, ~ or none stays as it was.
  • Only what's shown. a and i act on the packages currently visible, so a filter narrows what they touch.

Overrides

See what your overrides really do

Overrides come from overrides (npm, bun), resolutions (yarn, bun) or pnpm.overrides (pnpm). Press o to list them under each package.

     ├─ qs → override ^6.11.0  ⇢ ^6.14.1  (via body-parser)
     └─ path-to-regexp → 0.1.12
○ react-dom  ⚑   dep ^18.2.0  → ^19.0.0
○ typescript ⚠   dev ~5.3.0   → ~5.7.0  conflicts with override
○ semver     ?   dep ^7.5.0   → ^7.6.0  override can't be read
○ minimist         dep ^1.2.0   ✂ may be removed
MarkerMeaning
⚑The package itself is overridden, and the update is compatible.
⚠The update conflicts with its override.
?The override can't be interpreted (URL, alias, odd range).
↳An override applies somewhere in the package's installed dependency tree. Yellow if it forces a version outside what the parent declares.
✱A scan found vulnerabilities, colored by worst severity.
✂The override may no longer be needed.

Compatibility check

npm needs an override on a direct dependency to match its spec exactly, or it fails with EOVERRIDE. yarn, pnpm and bun let the override win silently. depsu applies the right rule and asks for a second keypress before a conflicting update.

Dependency tree walk

Walks node_modules, including pnpm's symlinked layout, and lists every override that applies to a dependency at any depth, with the chain that leads to it.

Update overrides

Lines with a plain version or range show ⇢ new value. Select them and press i. package.json is edited in place, keeping indentation, key order and the trailing newline.

Overridden-only packages

A package that is overridden but not a dependency gets its own ovr row at the bottom of the list. Update it like any other.

Unneeded overrides

Flagged ✂ may be removed when nothing depends on the package, every dependent asks for the same spec, or every dependent already requires at least that version. Remove them with d.

Pin a fix

When a scan reports a vulnerable nested package with a fixed version, p adds an override to ^<fixed version>. It asks for a second press and warns that forcing a version can break dependents.

Vulnerabilities

Find them. Fix them. From the same list.

Findings appear under the direct dependency that brings them in, with severity, ID, CVE, the vulnerable package, the path to it, and what to do about it.

Snyk (s)

Runs snyk test --json --dev. Works with any package manager. Needs the Snyk CLI and snyk auth. It sends your dependency list to Snyk and counts against your quota, so it never runs automatically.

npm audit / bun audit (n)

Runs the project's own audit command. No account needed. Findings are tagged [npm audit] or [bun audit] so both can show at once. Not available for yarn and pnpm.

One-key fixes

A fixable finding ends in green with the key that applies it: i installs the upgrade of the direct dependency, p overrides the nested package.

Details panel

Know what you are installing

Press ? on any package. Everything comes from disk, so nothing is downloaded.

  • Deprecation message and install scripts
  • Installed version, size and file count
  • Engines checked against your installed node, npm and package manager, plus os, cpu, libc
  • Lockfile integrity checksum
  • Dependencies and how they changed since the last commit
  • Installed packages that use it, and peers with installed versions
  • Override summary

Inline warnings appear in the list even when the panel is closed: ⚠ needs node >=20 (has 18.19.0), ⚠ unmet peer, ⚠ no integrity checksum.

Editing

Change anything from a dialog

Every change goes through package.json and your package manager, with the same peer and blocked-version checks as i.

Edit a version (e)

Pre-filled with the current version, e.g. ^18.3.1. Go older or newer and change the pin type. While you type, the dialog says whether that version is published and names the nearest ones if not.

Add a package (+)

Type name for latest, or name@1.2.3. Pick dependency, dev dependency or override with Tab. The registry is checked first and problems show in the dialog.

Choose the pin (P)

Exact (e), caret ^ (c), tilde ~ (t) or at least >= (m). Letters are used because ^ and ~ are dead keys on Nordic keyboards.

Delete (d)

Removes checked packages and overrides in one go. A dialog lists what will be uninstalled, warns about installed packages that use them, and asks to confirm. Restore with r.

Fix unmet peers (f)

For a package marked ⚠ unmet peer, depsu looks up fitting versions: update the peers into the requested range, or move the package up or down to a version that accepts what is installed.

Checksums (I)

Adds a missing integrity checksum to package-lock.json, the one the registry publishes for the locked version. It is written only when the registry's file matches the lockfile's resolved.

Blocked versions. Registries with a security policy (JFrog Curation, Nexus Firewall and similar) list blocked versions but answer 403 on download. depsu checks every version before installing, tries up to 15 older releases, and offers the newest that works. The fallback is pinned exactly, because a range would resolve to the blocked version again.

Git

Commit what you changed

Press c to commit package.json and the lockfile. Other staged or modified files are left alone. Git hooks run, and if one fails its message is shown and nothing is committed.

  • Conventional title built from what changed since the last commit, shortened to fit 72 characters.
  • Body lists every change the title doesn't already say.
  • Fixes: section lists vulnerabilities fixed this session, with ID, title and severity.
  • Checksum changes from I are their own change.
  • Editable. Tab switches between title and body. Ctrl+S commits from either.

Registry and authentication

Works with private registries

For each package, depsu picks the registry the way npm does and sends the matching token. Tokens for a custom registry are never sent to registry.npmjs.org or registry.yarnpkg.com.

npmyarnpnpmbun

.npmrc

Project, then ~/.npmrc. Supports registry, @scope:registry, _authToken, _auth, username with _password, and ${VAR} or ${VAR:-default}. NPM_CONFIG_REGISTRY overrides the default.

bunfig.toml

For bun projects, project then ~/.bunfig.toml. Supports [install] registry, [install.registry] with url, token, username and password, and [install.scopes].

.yarnrc.yml

For Yarn 2+, used instead of .npmrc, merged from ~/.yarnrc.yml down to the nearest file. Supports npmRegistryServer, npmAuthToken, npmAuthIdent, scopes and per-registry entries, plus YARN_NPM_* variables.

Package manager detection

The packageManager field wins. Otherwise depsu looks for bun.lock, pnpm-lock.yaml, yarn.lock or package-lock.json in the project and its parents. Falls back to npm. Override with --pm.

Same way as ncu

Requests use the abbreviated (corgi) Accept header and stop reading once dist-tags has been seen, with a full-document retry on 404.

What counts as outdated

The lowest version of each range is compared with the registry's latest tag. Prereleases are ignored. git, file:, workspace:, npm: aliases, tags and || ranges are skipped.

Get started

Install and run

depsu is written in Rust and needs a Rust toolchain to build.

# clone the repository
git clone https://github.com/joonakeskitalo/depsu.git
cd depsu

# build and install to ~/.local/bin (override with PREFIX=/usr/local)
make release
make install

# or
cargo install --path .
# run in a project directory
depsu
depsu --dir ../other-project
depsu --pm pnpm                    # skip detection
depsu --cache .depsu-cache.json    # remember versions and scans between runs
OptionDescription
-C, --dir <PATH>Project directory (default: current directory)
--pm <NAME>Force the package manager: npm, yarn, pnpm or bun
--cache <FILE>JSON file for latest versions and Snyk / audit findings. One file can be shared by several projects: versions are shared, scan results are kept apart per project directory. A file that can't be parsed is left untouched and not used.
-h, --help / -V, --versionHelp and version
Good to know

Limitations

  • Only the latest dist-tag is considered. There is no --target minor or patch.
  • Yarn Classic's .yarnrc and overrides in pnpm-workspace.yaml are not read. Yarn Classic still gets its registry from .npmrc.
  • Override analysis reads node_modules, so it finds nothing with Yarn Plug'n'Play or before the first install.
  • npm audit and bun audit findings need installed dependencies. Bun's fix plan was checked only with Bun 1.4.5, and older versions have no bun audit.
  • The unneeded-override check is a heuristic. Verify before removing.
  • Not tested on Windows.
